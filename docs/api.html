moonjson

The tree every dialect reads into, the scanner they share, and the writer that puts it back as strict JSON.

JSON with comments and trailing commas — what editors and their configuration files have settled on, tsconfig.json being the best-known.

dump

The same, as UTF-8 bytes — the form a body goes onto a wire in.

dumps

pub fn dumps(Json, indent? : Int32, ascii? : Bool, sort? : Bool) -> String

Write a tree as strict JSON, whatever dialect it was read from.

indent of zero, the default, writes the compact form with no space anywhere; anything larger writes one line per member with that many spaces a level, and a space after each colon.

A number that came in as text goes back out as that text, so a document read and written again is unchanged. Only a number with no such text is formatted, and a number that is not finite — which JSON5 can produce and JSON cannot write — becomes null, as every JavaScript implementation does.

load

pub fn load(BytesView, Flavor, bom? : Bool) -> Json raise Refused

Read one document from bytes, which is how one arrives over a wire. A leading byte-order mark is skipped by default. RFC 8259 §8.1 forbids writing one and says nothing about refusing to read one, and refusing would mean rejecting half the files Windows tooling produces.

loads

Read one document in the given dialect.

The whole input must be one value: anything after it, other than whitespace and — where the dialect allows them — comments, is Trailing, not silently ignored. A parser that stops at the first value turns a truncated file into a plausible one.

Flavor

pub(all) struct Flavor

How to read a document: what syntax to accept, and what to do at the edges.

The dialects in this family differ only in their syntax — the tree they produce is the same — so the scanner is written once and each dialect is a set of switches. A dialect outside this repository can be described the same way without forking anything.

The last three fields are not syntax but policy. They are here rather than as arguments because they are set once for a deployment and because this family has sixteen entry points: a policy added here costs one line, and a policy added to every signature costs sixteen.

Fields
  • comments : Bool

    // to end of line, and /* … */.

  • trailing_commas : Bool

    A comma before the closing brace or bracket.

  • unquoted_keys : Bool

    A member name written as an identifier rather than a string.

  • single_quotes : Bool

    'like this' as well as "like this".

  • extra_numbers : Bool

    +1, .5, 5., 0xFF, Infinity, -Infinity, NaN.

  • extra_escapes : Bool

    \x41, \0, \v, a backslash before a newline, and a backslash before anything else standing for that character.

  • extra_space : Bool

    The whitespace ECMAScript recognises, not only the four RFC 8259 allows.

  • depth : Int32

    How deep the nesting may go before the document is refused.

    Five hundred is past anything written for a reader and far short of what exhausts a stack on any backend. Readers disagree on the number — a thousand in one, a hundred and twenty-eight in another — but not on having one, because a document of a hundred thousand open brackets is a denial of service rather than a document.

  • surrogates : Bool

    Whether a lone half of a surrogate pair is a character.

    The case is implementation-defined: a reader may keep the half, replace it with U+FFFD, or refuse the document. This one refuses, because a lone half cannot be written back out and every value that could replace it is a guess about what the writer meant.

  • duplicates : Duplicates

    What a repeated member name means.

Refused

pub(all) suberror Refused

Why a document was refused, and where.

One error type for the whole family — reading text, reading bytes, walking a pointer, applying a patch, writing a value a format cannot carry — so that a caller has one thing to catch and one place to look. A variant that has a position carries the At it was found at; a variant about a pointer or a patch names the pointer itself, because a move and a copy each carry two and an error that did not say which one would be half an error.

Variants
  • Unexpected(At, Char)

    A character that cannot start or continue what is being read.

  • Truncated(At)

    The document ends inside a value.

  • BadEscape(At)

    An escape sequence that is not one, or a lone half of a surrogate pair.

  • BadNumber(At)

    A number the grammar does not admit — a leading zero, a bare minus, an exponent with no digits.

  • Trailing(At)

    A second value after the first one ended.

  • TooDeep(At)

    Nesting past the depth limit. Without this, a document of ten thousand open brackets would take the stack down with it.

  • BadUtf8(At)

    Bytes that are not UTF-8, when reading a document that arrived as bytes.

  • Repeated(At, String)

    A member name that appears twice, when the dialect refuses that.

  • Short(at~ : Int32)

    The document ended inside a value.

  • Extra(at~ : Int32)

    Something after the value ended. A document is one value, and a reader that stops at the first turns a corrupt file into a plausible one.

  • Bad(at~ : Int32, why~ : String)

    A byte that cannot be read this way: a reserved additional-information value, a length or an index that does not fit, a string that is not UTF-8, a nesting that went too deep.

  • Unwritable(why~ : String)

    A value the format has no way to write: a number that is not finite into JSON, a byte string into a text dialect, a key that is not a string into one whose objects have only string keys.

  • Syntax(path~ : String, at~ : Int32)

    The pointer is not one: it does not start with a slash, or a ~ is followed by anything but 0 or 1. at is the offset within path.

  • Missing(path~ : String, token~ : String)

    What the pointer names is not there: a name no member has, or an index no array reaches.

  • NotContainer(path~ : String, token~ : String)

    The pointer walked into something that is neither an object nor an array.

  • BadIndex(path~ : String, token~ : String)

    An array index that is not one — not decimal digits without a leading zero — or - where it does not mean append.

  • Document(why~ : String)

    The document is JSON but not a patch: not an array of operations.

  • Operation(at~ : Int32, why~ : String)

    The operation at at is not one: no op member, an op that is not one of the six, or a member it requires missing or of the wrong type.

  • TestFailed(path~ : String)

    A test that did not hold.

  • IntoChild(from~ : String, path~ : String)

    A move into one of the moved value's own children (RFC 6902 §4.4).

  • Root(path~ : String)

    The operation names the root, which has no parent to take it from.

Methods

    Where the failure happened, when it happened in text.

    None is not a failure to say: a pointer or a patch that was refused has a path rather than a line, and a line number invented for it would be worse than no line number at all.

The sentence is lower case and carries no full stop, so a caller can put it after its own word — "refused: " + error.message() — without the punctuation fighting.

remove

pub fn remove(Json, StringView) -> Json raise @moonjson.Refused

Take away whatever pointer leads to, and answer the document that results.

RFC 6902's remove: the member or the element must be there, because taking away what was never there is a request nobody can have meant. The root cannot be removed — an empty pointer names the whole document, and there would be nothing left to answer with.

set

pub fn set(Json, StringView, Json) -> Json raise @moonjson.Refused

Put value where pointer leads, and answer the document that results.

The semantics are RFC 6902's add and replace taken together: a member or an element that is already there is replaced, one that is not is created, and - as an array index appends — which is the one place RFC 6901 §4 says that token means something, and the reason get refuses it.

It answers a new document rather than changing the one it was given. A tree is shared: a value reached through two pointers is one value, and editing it in place would change both. Only the path from the root to the edit is rebuilt; everything else is the same value it was.

moonbit nocheck
let cfg = @pointer.set(cfg, "/spec/replicas", Json::number(5))

package

patch

A patch document is an array of operation objects, each naming one change — add, remove, replace, move, copy or test — against a target document. It is read into Operations rather than left as a tree of objects, because the six share nothing but their shape: two carry a value, two carry a second pointer, and a document whose op is misspelled is a document that would quietly do nothing.

apply

pub fn apply(Json, ArrayView[Operation]) -> Json raise @moonjson.Refused

Apply a patch to a document, and answer the document that results.

The operations are applied in order, each to the result of the one before it. A patch that fails partway applies nothing: the document it was given is never changed, and the answer is the error rather than half a document — RFC 6902 §5 says that if any operation is unsuccessful, application of the entire patch document is not deemed successful.

It answers a new document rather than changing the one it was given, for the same reason @pointer.set does: a tree is shared, and a value reached through two pointers is one value.

Operation

pub(all) enum Operation

One operation in a patch document, as RFC 6902 §4 names the six.

Variants
  • Add(path~ : String, value~ : Json)

    Put value where path leads (RFC 6902 §4.1).

    An object member that is not there is created, one that is there is replaced, and an array element is inserted — the elements at or above the index shift one place to the right — with - appending at the end. The root is a target too: an add to the empty pointer makes the value the whole document.

  • Remove(path~ : String)

    Take away what path leads to (RFC 6902 §4.2).

    It has to be there: taking away what was never there is a request nobody can have meant. The root cannot be taken away — the empty pointer names the whole document, and there would be nothing left to answer with.

  • Replace(path~ : String, value~ : Json)

    Replace the value at path (RFC 6902 §4.3).

    The target has to be there already; this is add without the creating.

  • Move(path~ : String, from~ : String)

    Take the value at from away and put it at path (RFC 6902 §4.4).

    from must not be a parent of path: a location cannot be moved into one of its own children.

  • Copy(path~ : String, from~ : String)

    Copy the value at from to path (RFC 6902 §4.5).

  • Test(path~ : String, value~ : Json)

    Require the value at path to equal value (RFC 6902 §4.6).

    Equality is the tree's: a number equals the same number written another way, because the tree holds a number as a number and not as text.

package

merge

A merge patch has no syntax of its own: the patch document is a JSON document, read with @json.loads like any other. What this package adds is the evaluation — the rules that say which members of the target are added, replaced or taken away — so there are no loads and dumps here. The four faces belong to formats, and the format is plain JSON.

merge

pub fn merge(Json, Json) -> Json

Apply a merge patch to a document, and answer the document that results.

A merge patch looks like the document it changes rather than like a list of instructions: a member that is not there is added, one that is there is replaced, and a member whose value is null is taken away — a null in the patch is an instruction, while a null already in the target is data and stays. A patch that is not an object replaces the whole document, null itself among them, and a target that is not an object is ignored and started again from an empty one.

It answers a new document rather than changing the one it was given, for the same reason @pointer.set does: a tree is shared, and a value reached through two pointers is one value.

moonbit nocheck
let cfg = @json.loads("{\"host\":\"localhost\",\"port\":8080,\"tls\":false}")
@merge.merge(cfg, @json.loads("{\"port\":9090,\"tls\":null}"))
// {"host":"localhost","port":9090}

package

jcs

One tree, one document: JCS exists so that two parties can sign the same bytes. Nothing here is a knob, because a canonical form with options is not canonical — the numbers are ECMAScript's, the member order is UTF-16 code unit order, and a number that is not finite is refused rather than spelled some way we invented.

dump

pub fn dump(Json) -> Bytes raise @moonjson.Refused

The same, as the UTF-8 bytes a signature is taken over.

dumps

pub fn dumps(Json) -> String raise @moonjson.Refused

The canonical form of a tree, as RFC 8785 writes it.

Members are ordered by their names compared as UTF-16 code units — not as code points, which differ for anything above U+FFFF — numbers are written the way ECMAScript writes them, and nothing is escaped that does not have to be. Two trees that hold the same values therefore come out as the same bytes, which is the whole point: a signature over these bytes is a signature over the document.

A number that is not finite cannot be written, because the RFC's number serialisation is ECMAScript's and ECMAScript has no syntax for it. It is refused rather than replaced with null or 0, either of which would sign something the document does not say.

cbor

CBOR is JSON's data model with the corners filled in: byte strings, integers that a double cannot hold, tags, and a distinction between false and undefined. It writes itself into a tree the rest of this family already understands, and what the tree cannot hold outright is carried in the markers documented on load — so a CBOR document can be read here and written as JSON, and a JSON document can be written here and read there.

A reader that needs the name or the type must read the key string and divide it on the last :. This is the faithful and honest reading: a tagged value is valid JSON, and nothing here pretends otherwise.
