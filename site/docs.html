the surface

One set of verbs

The verbs Python's json, PyYAML and tomllib share. The s is on the form that takes or answers a string, as it is in Python.

text → tree bytes → tree tree → text tree → bytes
one document loads load dumps dump
a stream of them loads_all load_all dumps_all dump_all

The plural set exists exactly where the format defines a stream — lines is a stream and has only those; json, jsonc and json5 define one document and have only the singular set.

Not from_str and to_string: to_string already means Show::to_string in MoonBit, and @json.to_string(x) beside x.to_string() is a sentence that reads two ways.

the packages

A package per way of writing it

Each has the same four faces, so learning one is learning all of them. Writing is always strict JSON, whatever the document was written in.

json

JSON, exactly — RFC 8259 and ECMA-404. The grammar and nothing more: no comments, no trailing comma, no leading zero, no unquoted name, no control character inside a string. Everything the grammar refuses is an error naming the line and the column.

jsonc

JSON with comments and trailing commas — what editors and their configuration files have settled on, tsconfig.json being the best-known.

json5

JSON5: unquoted names, single quotes, hexadecimal, Infinity, NaN, and the whitespace ECMAScript recognises. It carries values JSON has no syntax for; those go back out as null, as every JavaScript implementation writes them.

lines

JSON Lines, also called NDJSON: one document to a line, separated by a line feed, each one complete. It is what a log file or a stream of records is written as, because a reader can start anywhere and a writer can append without rewriting. Every line it writes ends in a feed, including the last.

pointer

JSON Pointer, RFC 6901: a string that names one place in a document. ~1 stands for a slash and ~0 for a tilde, undone in that order — the other way round would turn ~01 into a slash. get, has, set, remove, tokens, escape and join.

patch

JSON Patch, RFC 6902: a patch document is an array of operation objects — add, remove, replace, move, copy, test — applied in order, or, if one fails, not at all. It is read into Operations rather than left as a tree of objects, so a misspelled op is an error rather than a document that quietly does nothing.

merge

JSON Merge Patch, RFC 7396: a patch that looks like the document it changes. A member that is not there is added, one that is there is replaced, and a member whose value is null is taken away. A merge patch has no syntax of its own — the patch document is a JSON document, read with @json.loads — so this package holds the evaluation and nothing else, and it never fails.

moonjson

The root package: the scanner the dialects share, the writer that puts a tree back as strict JSON, the Flavor record, and Refused.

reading

How to read is a value

Flavor carries both what syntax a dialect accepts and what it does at the edges — how deep the nesting may go, what a lone surrogate means, what a repeated member name means — and every reader takes one.

moonbit
@json.loads(text)                                     // strict JSON
@jsonc.loads(text)                                    // the same, plus comments
@json.loads(text, flavor=@moonjson.Flavor::new(depth=100))
@json.loads(text, flavor={ ..@moonjson.strict, duplicates: Reject })

Two layers, the later overriding the earlier: the dialect's preset < the flavor you pass. The two ways of building one — the constructor and the record update — are the same thing.

Setting Default Why that one
depth 500 Everyone bounds it and nobody agrees on the number — Jackson refuses past 1000, serde_json past 128. A hundred thousand open brackets is a denial of service, not a document.
surrogates refuse Implementations disagree and JSONTestSuite files these cases as implementation-defined, so the safer side is the default: a lone half cannot be written back out.
duplicates Last JavaScript, Python, Go and serde all keep the last one.
bom skipped RFC 8259 §8.1 forbids writing one and says nothing about reading one; refusing would reject half of what Windows tooling produces.
ascii off A UTF-8 body is the normal case now. Python's ensure_ascii defaults the other way because it predates that.
sort off The order a document was written in is information; a diff is the reason to discard it, and a diff can ask.
the tree

Core's Json, not one of our own

Anything that already speaks @json.Json speaks this, with no conversion.

A number keeps the text it was written as, so a document read and written again comes back unchanged — including a twenty-digit integer and 1e400, which a double cannot hold and which a parser that goes through one silently rewrites. A number JSON has no syntax for, which JSON5 can produce, is written as null, as every JavaScript implementation writes it.

Members keep their order.

changing

Changing a document

Three ways, for three kinds of change. One place is named with a pointer (RFC 6901); a set of changes that must all hold or none is a patch (RFC 6902); and a change that looks like the document itself is a merge patch (RFC 7396).

moonbit
// One field, and nothing else changes.
let cfg = @pointer.set(cfg, "/spec/replicas", Json::number(5))

// Six operations, applied in order — or, if one fails, not at all.
let ops = @patch.loads(
  "[{\"op\":\"test\",\"path\":\"/spec/replicas\",\"value\":1},{\"op\":\"replace\",\"path\":\"/spec/replicas\",\"value\":5}]"
)
@patch.apply(cfg, ops)

// A patch that looks like the document: a member that is not there is added,
// one that is there is replaced, and a null takes one away.
@merge.merge(cfg, @json.loads("{\"spec\":{\"replicas\":5,\"image\":null}}"))
the pointers inside a patch They are @pointer's. The syntax, the escapes and the refusals come from there, said about the member that named them, so one implementation of RFC 6901 serves both packages.
failures

What went wrong, and where

Reading raises Refused, which says what went wrong and where — offset, line and column. Nesting is refused past 500 levels rather than taken to the stack.

moonbit
try @json.loads(source) catch {
  e => println("line \{e.at().line}, column \{e.at().column}")
}

A patch has its own failure type, @patch.Failure: the scanner's, wrapped as Unreadable; a document that is not a patch; a pointer that is not one; a target that is not there; a test that did not hold; a move into a child; and the root, which has no parent to take it from. A patch that fails partway applies nothing — the document it was given is never changed.

checked

What is measured, and against what

  • The strict parser, against cases drawn from JSONTestSuite — every verdict taken from a third-party parser rather than asserted from memory: 95 documents that must be accepted or refused, and are.
  • JSON5, against the document json5.org puts on its front page.
  • JSON Pointer, against every example RFC 6901 §5 prints.
  • JSON Patch, against every example RFC 6902 Appendix A prints.
  • JSON Merge Patch, against every case RFC 7396 Appendix A prints.

Four backends — wasm, wasm-gc, js and native — run the whole suite on every push.

roadmap

What is not here yet

Planned in this order; the tracking list lives with the project.

  • Hjson and the other text dialects.
  • CBOR, MessagePack, BSON and the other binary encodings.
  • PostgreSQL's and SQLite's jsonb.
  • JSONPath, JSON Schema and canonical serialisation.

YAML and TOML are their own repositories. HOCON and HCL belong with configuration, because their substitutions and merges are evaluation, not syntax.
